## 工具:tools/storyboard_regen.py

两阶段批量重写(LLM 逐章):
1. **分镜表生成**(JSON:章衔接 + 每镜景别/运镜/画面/台词/光影/音效/时长/登场角色)
2. **逐镜六段式生成**(Ref2VA,上镜收尾链式承接,章内串行)

确定性修复层(程序兜底,LLM 不可靠处全部机械修正):
- 语音预算时长修正 + **超 75 字长对白镜自动拆镜**(引号单元/句末标点切分,新镜
  「角色继续说」承接,时长按字数计算)——修复 LLM 把 100+ 字对白堆一镜的顽固行为
- 说话人 Sx 跨镜统一(按全集首次发言序,修复 ID 翻转)
- >20 字长句拆多引号连写
- 标点以正文为准(半角/全角混合问题:正文对白列表直供 LLM 照抄 + 程序匹配替换)
- `<d>` 标签补写兜底(LLM 漏写 <d> 时按台词列补画外音/对白标签,渲染必有配音)
- summary [reference generation] 前缀、时间戳按时长累进重写

校验与重试(三层闭环):
- 正文对白 → 台词列 → `<d>` 逐字覆盖(漏挂带正文上下文反馈重试;非对白引号词
  按言语语境豁免——「的"黑色剪纸"」「想想,没写」类不算对白)
- 六段式六字段完整/内心镜 Q 版主体/语音预算,失败带质检反馈重试(单镜 4 次 +
  整章 3 轮)
- 断点续跑(resume 只跳过带重写标记的文件)、章节并发、失败清单

## 过程中的关键坑(均已解决)

1. **deepseek-v4-flash 是推理模型**:长输入 reasoning 吃掉 17k-20k tokens、
   单次 2-5 分钟且 content 常空返回——批量工具改用 **deepseek-chat**(19s/次稳定)
2. **正文半角/全角标点混合**:storyboard_check 的 norm 只剥全角标点,LLM 转全角
   即覆盖比对失败——正文对白列表直供 + 程序标点修复
3. **文学性引号词误判漏挂**:「黑色剪纸」「预报中的全城雷雨」非对白——言语语境
   判定豁免(单元后 20 字含说/喊/问等言语动词才算对白;「想想,没写」类豁免)
4. **语音预算**:LLM 反复把 100+ 字对白堆一镜(反馈 3 次只挪镜不拆)——程序拆镜
   兜底 + 时长按字数计算
