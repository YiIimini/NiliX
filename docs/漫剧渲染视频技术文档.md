## 3. 管线总流程

```
小说正文 → [plan] LLM 分镜+角色/场景卡+H3 提示词
         → [assets] 定妆照/场景图(抽卡/采纳/上传)
         → [encode] Qwen3-VL 条件缓存(.pt)
         → [render] H3 视频生成(Ref2VA 锁角色 / FL2VA 空镜 + MotionContext 接缝)
         → [qc] 机械质检(PyAV)+ 视觉审片(AI 一条龙)
         → [assemble] 成片(转场/BGM/字幕/马赛克)
         → [upscale 云端2K] / [jianying 剪映导出] / [trailer 预告片]
```

- **阶段按钮**:⓪项目体检 ①方案 ②资产 ③编码 ④渲染 ⑤质检 ⑥合成;「一条龙」= 全阶段顺序执行;「AI 一条龙」= 智能体调度;「▶ 续跑」= 幂等续跑。
- **运行参数**:章节(0=按小说总章数)、集数(0=每章一集自动分集;N>0=第 N 集=第 N 章)、镜头(可选,留空=全集)。

## 4. 方案生成 plan

**功能逻辑**: 读小说章节 → LLM(DeepSeek)直出分镜方案 JSON(角色卡/场景卡/镜头表/逐镜 H3 提示词),落 `analysis/<ep>_direct_plan.json`、`_characters.json`、`_shots_prompts.json`。已有方案幂等复用(输入变化才重新生成)。

**技术实现**:
- `stagePlan`(`manju_pipeline.go:950`):系统提示词 `manjuDirectSystem`(`manju_llm.go:380`)包含内容纪律/输出 JSON schema/分镜纪律/说话人纪律/时长硬约束;注入知识库模板(`knowledge` 节)与小说素材自动利用(scanNovelAssets 五类解析)。
- 镜头结构 `manjuShot`:`ID/Scene/Characters/ShotSize/Camera/Action/Dialogue/Narration/Duration/H3Prompt/TakeTail/TakeGroup`。
- 逐镜 H3 提示词:`genShotPrompts`(`manju_pipeline.go:1160`)worker 池并发(上限 4)调用 LLM 按 `manjuShotPromptSystem`(六段式 Ref2VA / 三段式 FL2VA)+ `manjuShotWritingRules` 直出。
- 时效:方案无分段标记时普通模式复用、全本自动分集视为过期重新生成。

## 5. 资产生成 assets 与角色管理

**功能逻辑**: 为方案每个角色/场景生成图片(定妆照/场景图/正脸参考),产出 `assets/` + `asset_map.json` 索引;抽卡是人工挑选定妆照的流程。

**技术实现**:
- 目录:`assets/characters/<id>.png`(定妆照)、`_face.png`(正脸参考)、`_gacha/`(抽卡候选)、`assets/scenes/<id>.png`、`asset_map.json`、`adopted.json`。
- **定妆照固定 1024×1024**(`manjuPortraitW/H`),与项目画幅/档位解耦——保证跨项目角色一致。
- 模型分流 `portraitWF`:`real` 风格用 Z-Image(turbo 8 步),否则 SDXL 按性别 `char_models[男/女]`。
- **正脸参考** `ensureFaceCrop`:从定妆照切上部头肩区(垂直 8%-52%),按渲染同比例输出(`--ratio WxH`)——`ref_image_size=match` 会缩放参考图,比例不符会压扁;脸部占满参考帧大幅增强 H3 身份锁定。
- 资产指纹 `assetsFingerprint`:characters+scenes 全部 png 的「文件名@mtime」MD5 8 位,作为条件缓存失效依据。
- **抽卡**:`POST /api/manju/gacha`(随机 seed 生成候选)→ `/gacha/adopt`(覆盖定妆照→mtime 变化→缓存失效→自动重新预编码/渲染)→ `/gacha/upload`(multipart,请求体≤64MB/单文件≤20MB,仅 png/jpg/jpeg/webp)→ `/gacha/plan`(生成角色方案)。

## 6. 预编码 encode

**功能逻辑**: 每镜跑 Qwen3-VL 文本编码 → 条件缓存 `.pt`(渲染阶段 `CondLoad` 复用),同条件镜头共享缓存,避免重复编码烧 GPU。

**技术实现**:
- 缓存路径 `<ComfyShared>/models/conditioning/<cacheName>.pt`。
- 缓存名 `shotCacheNameAt`:`<项目清洗>_<版本v2>_c<内容指纹>`;内容指纹 = MD5(`p=H3Prompt|w|h|len|chars|scene|prompt`)10 位;草稿/定稿分辨率独立记账。
- 帧数 `h3Length`:`H3 17k+5 网格`,对齐 24fps,范围 107~362。
- 工作流 `h3EncWorkflow`:有角色 → `MiniMaxH3ReferenceToVideo`(每登场角色一张参考图,正脸优先,最多 3 个);空镜 → `MiniMaxH3ImageToVideo`(场景首帧);输出 `CondSave` 写 .pt。
- 渲染期间**后台预编码下一镜**(与 GPU 渲染并行,空窗缩短)。

## 7. 渲染 render

**功能逻辑**: 把逐镜 H3 提示词 + 参考图提交 ComfyUI 生成视频片段,落 `clips/<ep>/NN.mp4`。跳过已存在产物;过期/0字节/质检未过自动删旧重渲。

**技术实现**:
- 工作流 `h3RenderWorkflow`(`manju_comfy.go:372`):UNETLoader → Turbo LoRA(参数表自动适配)→ PatchSageAttentionKJ(SageAttn,节点名双名探测)→ VAELoader → CondLoad → EmptyLatent → MotionContext 接缝 → KSampler → VAEDecode → SaveVideo。
- **提交/等待/取回** `renderShotTo`:`submit → renderCKSet(落盘 prompt_id) → wait(3600s,10s 轮询) → history 取产物 → copyFile → renderCKClear`;中断自动重试一次(更新检查点 pid)。
- **跳过/重渲判定**(`stageRender`):已存在 → 0 字节删重渲 / manifest stale 删旧重渲(含条件缓存)/ 定点重渲(镜头框 only 强制覆盖)/ 质检未过删旧重渲(轮数封顶 2)。
- **seed 策略** `seedFor(attempt)`:
  - `fixed`:首渲恒定;重渲(attempt>0)也 `seed+attempt`——**打破"重渲同画面永远不过质检"死循环**(曾是真 bug);
  - `increment`:`seed+attempt`;`random`:重试换随机。
- **分辨率档位** `manjuResTiers`:`draft 416 / standard 768 / fhd 1088`,按画幅等比换算短边、对齐 32(H3 VAE 32× 网格;1080 非 32 倍数故 fhd 用 1088);空/手动 = 直接宽高。 **768 是本地模型原生最优档**(官方面积上限 768×1344);**fhd 1088 超上限约 2 倍,慢 4 倍且质量不可控,仅实验位**——更高清晰度走云端 2K 精修。**画质档(2026-09-04 官方最佳实践默认)**:vae_video=fp16 + turbo_lora/turbo_lora_r2v=PDD Acc 8step + ref_image_size=max(身份保真更强);存量项目经 quality_gen=2 版本键一次性迁移;采样参数已进镜头指纹,改档自动全量重渲;要快出片可改回 4step LoRA + int8 VAE。
- **SageAttn**:`render.sage_attention` 开关;渲染前 `sageAttnGuard` 双名探测 `PathchSageAttentionKJ`(KJNodes 上游拼错名)/`PatchSageAttentionKJ`,节点缺失自动降级关闭(不阻塞渲染)。
- **ComfyUI 自动保障**:`ensureComfyReady` 渲染/资产/编码前确保在线,不在线自动拉起并等待就绪(120s)。
- 多切点长镜 `shots_per_take`:相邻同场景镜头合并一次生成,组内 `[Shot N] At MM:SS.mmm` 多机位切点。

## 8. 质检 qc 与审片

**功能逻辑**: 机械质检(PyAV:时长/音轨/近黑/解码)+ 视觉审片(AI 一条龙:八维度判分)。质检结果落盘报告,失败镜头渲染自愈重渲,并有逃生门。

**技术实现**:
- 机械质检 `stageQC`(`manju_pipeline.go:2042`)→ `manju_media.py qc`:近黑帧=整帧亮度<20(阈值 0.5)、静音=RMS<0.02、无音轨/解码0帧/时长<0.5s;报告写 `<项目>/qc/<ep>_qc.json`。
- **渲染自愈**:报告失败镜头下次渲染自动删旧重渲(轮数封顶 2,换 seed),渲染消费后清除报告。
- **逃生门** `POST /api/manju/qc/decision`:
  - `skip`(跳过失败镜):质检不计失败、合成排除(`qc_skip_shots` 合并去重);
  - `accept`(接受质检结果):失败不阻断、坏镜进成片(`qc_accept` 一次性,消费后清除)。
  - 前端中断横幅质检失败时显示失败镜头 + 「⏭ 跳过失败镜并续跑」「✅ 接受并合成」按钮。
- **审片八维度**(`internal/agent/agent.go`):identity 20 / action 15 / visibility 15 / tech 15 / scene 12 / camera 10 / style 8 / lips 5,合计 100;缺失维度 70 兜底标记 fallback。
- **ASR 台词核对**:whisper 转写对台词,与视觉判分并行。
- **终审官** `ArbiterDecide`:返工预算耗尽自动拍板(accept / 从零重写 regenerate),记入 `Judgment.Arbiter`,不等人。

## 9. 合成 assemble

**功能逻辑**: 镜头按序拼接成片:转场、字幕烧录、BGM 混音闪避、音量归一化、马赛克打码,输出 `<项目>/<ep>_成片.mp4`。

**技术实现**(`manju_media.py cmd_assemble`):
- 参数:`--clips-dir/--out/--episode/--fps/--mosaic/--plan/--transition/--trans-dur/--hard-cuts/--skip-shots/--bgm/--bgm-gain/--bgm-duck`。
- 转场:cut 硬切 / fade 闪黑淡入淡出 / dissolve 叠化;**接缝镜头强制硬切**(manifest Seam 标记,防叠化重影)。
- 字幕:`_load_subtitle_cues`(读 plan dialogue/narration,去「角色:」前缀)→ 镜头内 12%-92%、句内按字数加权分窗 → 帧底部居中烧录(微软雅黑加粗,半透明圆角面板,超 2 行缩字号)。
- BGM:32000Hz 循环补齐,对白时段闪避(ramp 0.3s 平滑)。
- 音量归一化:峰值<0.25 放大(≤4x)、>0.9 压限、<0.02 静音不放大。
- 成片规格:libx264 crf18 / yuv420p / AAC 32k stereo 128k / faststart;pts 显式单调递增。
- **跳过镜头**:`qc_skip_shots` 按补零名匹配剔除。
- 成片终检(agent 模式):单文件 qc,报告性质不阻断。

## 10. 智能体调度 AI 一条龙

**功能逻辑**: 剧本师复核 → 渲染 → 审片官逐镜判分 → 未达标修复师改写提示词排队重渲(预算内)→ 预算耗尽终审拍板 → 统一合成。

**技术实现**(`manju_agent.go agentRenderPipeline`):
- 逐镜「渲染 → 机械质检+ASR+视觉判分」当场审片,不合格修复提示词删产物重渲(每镜预算 `MaxRetries` 默认 2)。
- **草稿预审** `draft_judge`:审片轮用缩放分辨率草稿(`draft_scale` 0.2-0.95),全部落定后全分辨率定稿重渲(零返工)。
- 判分并发 `judge_concurrency`(1-4,默认 2);视觉模型 429 粘性降级(15min 冷却窗直连备模型)。
- **学习记忆** `agent_state.json`:高频问题 topN 反哺提示词生成(known_issues);风格选择记录。
- 终审 `auto_resolve` 默认开:预算耗尽 AI 决策 accept/regenerate,不阻塞成片。
- 视觉模型链:项目 agent 节 → 全局默认 → 项目 LLM Key → 环境变量 `GLM_VISION_API_KEY`。

## 11. 角色一致性保障

| 机制 | 实现 |
|---|---|
| 定妆照标准化 | 固定 1024×1024,与画幅/档位解耦 |
| 正脸参考 | `_face.png` 头肩特写,渲染同比例,脸部占满(Ref2VA 身份锁定主源) |
| 参考图纪律 | `ref_available` 名单=参考图顺序;`<Picture N>` 严格对应;Subject 编号一一对应,禁调换/跳过/合并 |
| 角色纪律 | 画面只允许 characters 列出的角色;未列出角色禁入画(远景剪影/虚化除外) |
| 主角中心 | 说话人/动作主角为视觉中心,其他人不得抢中心/遮挡 |
| 跨镜外观锁定 | 同一角色本集所有镜 Subject 描述逐字一致(以首镜为准),detailed_description 与 Subject 一致 |
| 外观锁定 | 外观只允许角色卡特征逐项覆盖,禁 generic 泛化词(ordinary/plain/sturdy)、禁编造(白发/换装/错年龄)、多角色镜禁串特征 |
| 产物时效 | manifest 指纹(stale → 自动删旧重渲) |

## 12. 提示词纪律体系

**分镜生成 `manjuDirectSystem`**:
- 台词/旁白逐字引用原文,禁改写/扩写/编造;关键事件必须有镜头,禁张冠李戴。
- **说话人硬约束**:dialogue 前缀"角色:"必须是在场角色,谁说的就是谁;角色台词一律放 dialogue,**禁混入旁白**;旁白仅承载原文叙述,禁含角色台词。
- duration 由台词量决定(中文 4 字/秒),台词截断=废镜。

**逐镜 H3 `manjuShotWritingRules`**:
- 说话者 (Sx) 按发声顺序、跨镜一致;发声者写 `<Subject N> (Sx)`。
- **台词必须对应角色开口**(`<Subject N> (Sx) says: <d>中文原文</d>`),禁安错人、禁改写成旁白。
- 旁白 = H3 原生画外音(narrator off-screen voiceover,画面人物闭嘴);**只有 narration 字段内容才写旁白,分镜 dialogue 禁转旁白**。
- 负面提示词逐概念转译正面排除句;known_issues 逐条正面规避。

## 13. 健壮性与崩溃恢复

### 13.1 渲染崩溃保护
- 管线 goroutine `panic recover`:崩溃不崩进程,记 `logs/crash.log`(堆栈)+ run.log,状态落盘失败(可续跑)。
- 灵动岛 goroutine / 自动恢复扫描均加 recover。

### 13.2 崩溃恢复续跑
`AutoRecoverRendering`(启动后 3s):扫描项目,磁盘 `run_state` running=true 且进程已死(崩溃残留)且阶段 ∈ {all, encode, render, qc} 且环境就绪(ComfyUI 拉起)→ `startManjuRun` 自动续跑。
> **坑**:前端一条龙发 phase="all",磁盘 Stage 恒落盘 "all"——白名单必须含 "all",否则永不自动恢复(已修)。

### 13.3 渲染检查点 `render_ck.json`
提交即落盘 prompt_id → 收产物即清;崩溃恢复 `tryReclaim` 查 ComfyUI history 收回「已提交未收」任务(已完成免重渲/在跑等完/丢失 90s 判定重新提交)。
> **坑**:重渲路径(attempt>0/fresh)必须跳过 tryReclaim,否则收回旧产物覆盖重渲(已修);删产物(clearShotArtifacts)同步清检查点。

### 13.4 看门狗守护
`NiliX.exe --watchdog <主进程PID>` 子进程监控主进程:
- 异常退出(崩溃/强杀,无 `logs/graceful_exit` 标记)→ 写 `logs/watchdog.log` 并自动重启;
- 用户主动退出(onExit 写标记)→ 不重启。

### 13.5 状态机
`manjuState` 内存态(锁保护)+ `run_state.json` 磁盘态;落盘含 PID(`isPidAlive` 存活判定依据);续跑累加 `baseElapsed`。

## 20. ai-film-skills 整合(2026-08-22)

> 来源:[L-Trunks/ai-film-skills](https://github.com/L-Trunks/ai-film-skills)(本地 AI 短片导演经验库,全部知识为实测/转述标注)。完整分析与逐条对照见 [`docs/ai-film-skills-深度解析与管线整合.md`](./ai-film-skills-深度解析与管线整合.md)。此前已整合的提示词纪律(规则 14-18:状态变化画之前/关系感物理动作/零数字/同机位接戏/导演备注祈使句)本节不重复。

### 20.1 反同质化指纹机制(新增 `manju_fingerprint.go`)

**问题**:NiliX 每集方案独立 LLM 直出,无防重复机制——连续多集可能长成「线性+全知+匀速+BGM通铺+空景收」同一个默认组合。

**机制**:
- plan JSON 新增 `directing` 对象(五维变量表 + signature 手法):

```json
"directing": {
  "time": "线性|倒叙|循环|平行切|单时刻切片",
  "pov": "全知|跟随单人|监控·仪器|物的视角|缺席",
  "tempo": "匀速|加速爆发|前紧后松|两次呼吸|全片凝滞",
  "audio": "BGM通铺|对白驱动|音效驱动|环境声|完全静音|声画错位",
  "ending": "空景收|回到首镜|硬切黑|悬而未决|日常化",
  "peak_device": "全片情绪最高点手法(写手法不写题材)",
  "climax_pattern": "高潮段镜头组织方式"
}
```

- 指纹落盘 `<项目>/analysis/fingerprints.jsonl`(每集一行,同集号幂等替换;方案复用也回填)。
- **生成前**:同小说历史摘要注入系统提示词(【防同质化·历史冲突警告】),要求五维与近 3 集拉开距离。
- **生成后**:`validatePlan` 复查——`vars` 撞 ≥3 维(近 3 集)→ 判问题进「带意见修复重试」闭环;`signature` 撞 ≥2 项(同小说全部历史:镜头数 ±10%/首尾景别/高潮手法精确匹配)→ 判问题;修复不了沿用原方案(不阻断)。
- **分集例外**(仓库明文):同一小说各集 `structure` 层不查;`vars`/`signature` 照常逐集查。
- 局限:文本撞维用精确匹配(仓库原版为语义等价判定),语义层由 LLM 在警告中自行判断。

### 20.2 方案提示词增补(`manju_llm.go manjuDirectSystem`)

- **判停清单**:模型做不到的六类换写法不重抽——机械开合→硬切空镜对比;群体连锁反应→单人反应+画外声;走位→直接画「已到位」(原地姿态变化可以);画内文字→只留大号阿拉伯数字;多人互动→拆单人镜视线缝合;手部纹理→姿势级特征。
- **题材真实度判据**:戏剧强度越高越假(火山/冰川/闪电是过拟合区),普通瞬间才真;高危画面改拍痕迹/后果。

### 20.3 逐镜 H3 规则增补(`manjuShotWritingRules` 规则 19-21)

| 规则 | 内容 | 来源 |
|---|---|---|
| 19 缺席表达 | 某物不在场但留下痕迹→否定句逐项列全(「没有人」无效) | prompt-craft 三-C |
| 20 构图权重之争 | 指令句被描述稀释→夹句(首尾各一遍)/画幅裁切(物理塞不下);堆形容词无效;水平左右位置提示词治不好 | prompt-craft 六 |
| 21 概念盲区判据 | 重渲错误方向与上次一致=盲区,禁止加词,改主体/换镜头设计 | prompt-craft 三 |

### 20.4 媒体脚本增补(`manju_media.py`)

- **qc 字幕位文字渗漏扫描**(默认开,`--no-ocr` 关闭):rapidocr_onnxruntime 可用时抽 3 帧,按「位置+宽度」判据(框中心 cy≥0.78 且 0.3≤cx≤0.7 且框宽>0.02)检字幕位文字(刺绣纹样等小框是噪声);未装时优雅跳过。检出即判质检失败,走既有重渲/逃生门。报告 JSON 每镜新增 `text_bleed` 字段。
- **bgm-pick 选曲子命令**:PyAV+numpy 零新依赖,逐曲算质心/滚降/低频占比(<500Hz)/调性,按仓库实测三档推荐(清新通透 ~2000Hz/~4200/15%/大调;深邃 ~1400/~2960/33%/小调;压抑惊悚 ~550/~440/61%);选曲前定档再找曲,别凭文件名;可定期体检曲库(重复文件/档位失衡会锁死创作多样性)。用法:`python manju_media.py bgm-pick --dir <曲库目录> [--json <p>]`。

### 20.5 判定不落地项(详见整合文档 §3.3)

链式锚定(Ref2VA 参考图已覆盖)、砍头保尾(预告片取中段同构)、误杀回归/冻结集合(建议作规则检查器上线前置纪律)、人脸一致性阈值 0.28(未用嵌入校验,若引入须本机标定)、云端重抽按钱判停(预算 2 轮已含成本)。

## 21. 视频脚本直出模式(2026-08-23)

> 与小说解析**并存的第二种方案输入方式**,前端「视频脚本直出」卡片二选一。官方格式依据:H3 官方指南本地副本 `manju-production 技能 references/官方提示词_官方指南原文/{base-en.txt, ref-en.txt}`(T2VA/I2VA/FL2VA/L2VA 三核心字段 + Ref2VA 六段式 + [Shot N] 时间码 + 运镜三要素 + 说话者 (Sx)/<d> 原文 + 画外音措辞 + <scenetrans>/<cutoff> + 可见文字引号)。

### 21.1 触发与数据流

```
config paths.script 指向脚本文件(<workdir>/script/<ep>.md) → newManjuCtx 进入 scriptMode:
  ctx.novel = 脚本文件(指纹/复用校验/章节标记全部复用)
  ctx.chapters 固定 "script"(脚本无章节概念,复用校验稳定;脚本文件指纹变化 → 方案自动重生成)
  ensurePlan:输入 = 脚本全文 + manjuScriptSystem → LLM 一步直出完整方案
    (characters/scenes/shots/directing + shots 每镜直接带 h3_prompt)
  genShotPrompts 自动跳过已有 h3_prompt 的镜 → 零中间步骤「脚本 → 渲染方案」
  小说素材注入跳过;防同质化指纹/判停清单/validatePlan 硬校验照常
```

### 21.2 `manjuScriptSystem`(manju_llm.go)

- 输入契约:符合 H3 官方规范的分镜脚本 md(镜头/时间码/画面/台词/音效/环境声/配乐,官方 prompt 形态或结构化分镜表形态均可)
- 输出 JSON 与小说模式一致(episode_title/characters/scenes/shots/directing),shots 每镜必带 `h3_prompt`
- 内嵌官方格式硬规定(三核心字段/Ref2VA 六段式/FL2VA 三段式/[Shot N]/运镜词表/(Sx)/<d>[中文]原文</d>/画外音+闭嘴/<scenetrans>/可见文字引号/无负面词转正面排除句)
- 拼接 `manjuRef2vaTpl/manjuFl2vaTpl/manjuShotWritingRules`,与逐镜生成格式严格一致
- 保留判停清单/题材真实度/面容独特性/防同质化 directing 五维纪律

### 21.3 前端
