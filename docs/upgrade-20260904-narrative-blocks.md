# 叙事块多镜合渲转正(2026-09-04 STEP 2)

## 背景与根因

用户主诉「H3 渲染毫无章法,完全是分镜脚本硬拼,没有故事线」。诊断三根因:

1. **切镜发生在视频之外**:逐镜独立渲染→MP4 顺序拼接,切点生硬;而 H3 官方支持
   单次生成内 `[Shot N] At MM:SS.mmm` 多切点叙事(叙事在视频内,衔接由模型原生完成);
2. 等长平铺无节奏(部分缓解);
3. 运动镜断链(已修)。

历史包袱:2026-08-26 万界召唤 16→8 事故后,脚本直出模式**禁用了 takes 分组**
(逐镜六段式是逐字权威,组头沿用单镜提示词渲染组和时长=整镜内容丢失)。根治
路径=**叙事块在分镜源头生成**(块级六段式覆盖组内全部画面与台词),而非渲染期
把单镜提示词分组。

## 架构(双端)

### 分镜脚本 JSON schema(技能侧)

```json
{
  "shots": [ ...逐镜数据+各自单镜六段式(编辑/回退/单镜重渲兜底,不变)... ],
  "narrative_blocks": [
    {"shots": [1, 2], "h3_prompt": "块级六段式:
      subject_definitions(组内并集,Picture/Audio 按挂载表编号)
      detailed_description 按切点分段:[Shot 1](首段无时码)→…→[Shot 2] At 00:06.000→…
      切点时码=前镜累计时长,clip-local"}
  ]
}
```

分组规则(契约 W,storyboard_check.py):同场景相邻 2-3 镜 / 时长和 ≤15s(API
上限,口径=语音预算补偿后的 plan 值)/ 登场 characters 并集 ≤3(挂载上限)/
块间不重叠 / 组内台词分句逐字进块 / 块内段间**禁承接句**(承接句是跨视频
MotionContext 接缝专用;块内切点是模型原生切镜,写了=矛盾)。

### NiliX 渲染端(internal/manju)

| 环节 | 行为 |
|---|---|
| parseScriptJSON | 解析 narrative_blocks(script_parse_ver=24) |
| attachNarrativeBlocks | 五重校验(连续/≤15s/切点标记/重叠/≥2镜),不过→降级逐镜(绝不丢镜);**块级六段式写进 plan 组头 h3_prompt**(与 LLM 多切点路径同款数据形态) |
| ensureTakes | 脚本直出保留 takes_src=blocks;旧启发式 takes 清除自愈不变 |
| ensurePlanAndPrompts | **applyTakes 提前到 finalize 前**——块提示词必过纪律注入/音色兜底/对齐层/写实化汇点(关键修复:首版内存覆盖绕过全部加工直交 H3) |
| applyTakes | 组头 Duration=组和(clamp 15)、TakeGroup/TakeTail、组内登场+台词旁白并组头(音色/QC 口径)、take_group 落盘(合成镜数口径) |
| selectedShots | 定点内镜号→组头整块重渲(废「静默空跑」) |
| qcGhostVoice | 组感知:头静尾说的块不判幽灵(防无限重渲循环) |
| 下游 | manju_media(qc/assemble/字幕)本就读 plan.takes 并组内核对——零改动复用 |

### 存量返工(tools/rework_narrative_blocks.py)

确定性分组(零 LLM)→ LLM 写块级六段式(挂载表/切点表直供编号与时码)→
校验闭环(W1-W5 + 台词列契约 + `<d>` 多重集 + 词数分级 250-600/780 + 整体
≤1250 词 + 不新增中文 + 说话者标签不减)→ 失败原因回灌重试 3 轮 → 部分成功
也落盘(失败块逐镜兜底)。嵌套 JSON 输出归一;.bak 保护;断点续跑(成功块
结果缓存,重跑零 LLM)。

试点实绩:被论斤第002章 8 块覆盖 19/24 镜(双端 PASS);递葫芦第002章 9 块
覆盖 25/28 镜(PASS);真实章全链 Go 回归:24 镜 → 13 渲染单元(块头全带
官方切点)。全库预案:三本 175 章 → 1980 块覆盖 89% 镜。

## 教训

1. **块提示词必须过 finalize 汇点**:首版在 applyTakes 内存覆盖组头提示词,
   时机在 finalize 之后→纪律/音色/对齐全被绕过。数据形态对齐既有 LLM 路径
   (块提示词进 plan)后,汇点自然覆盖——新路径优先复用既有数据形态,别造
   平行的内存通道。
2. **双端校验口径必须同源**:检查器按台词列整行探测 vs 工具按 `<d>` 多重集,
   各自都"对"却互相打脸;台词列才是分镜契约权威,分句(引号拆分)探测是
   正确形态(整行多句必误报)。
3. 语音预算补偿会把脚本时长撑大——块时长校验必须用 plan 补偿后口径(工具
   按脚本时长 15s 通过,解析后 24s 超限实锤)。
4. 词数目标必须写进 USER 消息并按块规模分级(单镜 dd 已 250-350,合块自然
   翻倍,统一 500 上限必误杀)。
